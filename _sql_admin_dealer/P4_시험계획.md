# P4 지역별 알림 시험 계획

모든 DB 시험은 `P4_지역별알림_DRYRUN.sql`을 Supabase SQL 편집기에서 실행한다. 이 파일은 트리거를 트랜잭션 안에서 비활성화하고 마지막에 `ROLLBACK`하므로 실제 알림·접수·설정은 남기지 않는다.

## 1. 기본값(끄기) 회귀

1. `system_config.regional_alert_mode`가 없거나 `off`인지 확인한다.
2. `region_id`가 NULL인 기존 건과 지역을 가진 시험 건 각각에 대해, 기존 승인/대기/순번 조건을 통과하는 팀장이 `leader_passes_region_filter`에서 모두 `true`인지 확인한다.
3. 순차 배정 `auto_assign_first_bidder`, 타임아웃 다음 후보, 비상 후보를 기존 기준 결과와 비교한다. `off`에서는 지역 조건 때문에 후보가 제외되면 안 된다.
4. send-alert는 `off`일 때 지역 RPC를 호출하지 않는 코드 경로이므로 기존 수신자/문자/푸시 수를 webhook 로그와 대조한다.

## 2. 켠 상태 공통 시나리오

지역이 지정된 시험 접수 건과 승인된 팀장 3명을 트랜잭션 안에 준비한다.

1. **지역 선택 팀장**: 해당 시·군·구(또는 그 상위 시·도)를 선택한 팀장은 후보 및 알림 대상이어야 한다.
2. **지역 미선택 팀장**: `partner_alert_regions` 행이 없는 팀장은 항상 후보 및 알림 대상이어야 한다.
3. **대상 없음**: 모든 승인 팀장이 다른 지역만 선택하고 미선택 팀장이 없으면 후보 함수는 NULL을 반환하고 `notify_escalation`/관리자 알림으로 대체되는지 확인한다.

## 3. 모드별 기대값

| 모드 | 건: 서울 종로구 | 팀장 선택 | 기대 |
| --- | --- | --- | --- |
| `sigungu` | 종로구 | 종로구 | 포함 |
| `sigungu` | 종로구 | 서울특별시 전체 | 포함 |
| `sigungu` | 종로구 | 중구 | 제외 |
| `sido` | 종로구 | 서울특별시 또는 서울의 어느 구 | 포함 |
| `sido` | 종로구 | 인천광역시 | 제외 |

각 모드에서 `SELECT public.leader_passes_region_filter(팀장ID, 건ID)`를 실행하고, 이어서 실제 배정 후보 및 send-alert webhook 로그를 대조한다. 운영에서는 DRYRUN을 쓰지 말고, Edge Function 배포 후에만 실제 알림을 제한된 테스트 번호로 검증한다.
