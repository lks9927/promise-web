## 4. RLS 단계 설계 메모

- 감사서의 12개 테이블: deposits, settlements, payout_requests, tax_invoices, bidding_history, coupons, partners, profiles, funeral_cases, flower_orders, notifications, system_config
- **Gemini 초안은 컬럼 이름 일부가 실제 스키마에 없다** (`bidder_id`, `orderer_id` 등). 그대로 쓰지 말고 실제 스키마로 다시 작성할 것. master가 하위 leader/dealer를 보는 **계층 규칙**도 빠져 있음.
- 속도 원칙: 정책은 `(select auth.uid())`로 감싸고, 역할은 JWT 클레임(`app_metadata.role`)으로 판단(행마다 서브쿼리 금지), 정책에 쓰는 컬럼에 인덱스.
- **쿠폰 링크 흐름을 깨면 안 됨**: 고객은 로그인 없이 링크에서 버튼 한 번으로 장례를 등록한다(`submit_emergency_case` RPC). `coupons`는 직접 조회를 막고 RPC로만 열어야 한다. `CouponLanding.jsx` 33~36행이 `coupons`를 직접 조회하므로 함수 호출로 바꿔야 RLS를 켤 수 있다.
- `submit_emergency_case` 점검 항목: 한 링크로 한 번만 등록(중복 방지), 속도 제한, 서버 입력 검증. 가짜 등록은 팀장 호출과 정산을 오염시킨다.
- 정산/출금: 금액은 클라이언트가 정하지 못하고 서버가 계산해야 한다(0건일 때 설계해 두기).

## 5. 배포 전 체크리스트 (모두 끝나기 전에는 배포하지 말 것)

1. **관리자 3명 비밀번호 변경** — 순서 중요: ① Supabase 대시보드 Authentication에서 Auth 비밀번호를 먼저 변경 → ② 그 다음 아래 SQL 실행.
   ```sql
   update public.profiles set password = null where role = 'admin';
   ```
   (남아 있는 옛 평문으로 이전 API가 Auth 비밀번호를 되돌릴 수 있기 때문)
2. **Vercel 환경변수**: `APP_API_TOKEN`, `VITE_APP_API_TOKEN`(문자 API 토큰), `SUPABASE_SECRET_KEY` 등록 확인. 없으면 알림 문자가 전부 401로 실패.
3. **미해결 버그**: 없는 전화번호로 `/api/legacy-login-migrate` 호출 시 401이 아니라 **500**. 로컬 `vercel dev` 창의 `Legacy login migration failed` 로그 줄로 원인 확인 필요(비밀번호 비교 함수는 오프라인 점검 통과 → DB 조회 쪽 추정).
4. **실행 테스트** (아래 7절 방법): 일반 가입 계정 로그인 / 틀린 비밀번호 / 관리자 복구 안내 / 레거시 이전 경로 / 지점·팀원 생성 / 관리자 비밀번호 초기화 / 로그아웃 후 보호 화면 접근 차단 / 로그인 후 localStorage `user`에 `password` 없음.
5. **기존 세션**: 배포 후 Supabase 세션 없이 예전 방식으로 로그인했던 사용자는 한 번 다시 로그인해야 한다.
6. **배포 직후**: DB의 `system_config`에서 `master_recovery_key` 삭제(기본값 `admin1234`, 현재 누구나 읽을 수 있음).
   ```sql
   delete from public.system_config where key = 'master_recovery_key';
   ```
7. **문자 테스트**: 쿠폰 문자, 팀장 배정 문자(문자 API 토큰 변경 영향).
8. **RLS를 켜기 전까지는 anon 키로 테이블을 읽고 쓸 수 있다.** 이전 API 경로의 완전한 차단도 RLS + `profiles.password` 열 삭제 이후에 완성된다. "배포했으니 안전"으로 보지 말 것.
9. 자동 백업 켜기(비용 여부 확인).

## 9. 라이젠 PC로 옮길 때 (인계)

1. **코드**: 이 브랜치는 그램에만 있다. 라이젠에서 이어가려면 `origin`(`lks9927/promise-web`)에 `v3-security`를 push해야 한다(외부 저장소에 올리는 작업이므로 사용자 승인 후). 미커밋 파일(`vite.config.js` proxy, `_audit/`, `nul`)은 올라가지 않는다. `nul`은 Windows가 만든 찌꺼기 파일이니 커밋하지 말 것.
2. **환경 파일**: `.env`, `.env.local`은 git에 없다. 라이젠에서 `vercel env pull`로 받거나 직접 복사. `.env.local`에는 **서버 비밀키**(`SUPABASE_SECRET_KEY`)가 있으니 대화나 문서에 값을 붙여넣지 말 것.
3. **도구**: Node, Vercel CLI 로그인, Codex(앱 갱신 시 실행 파일 경로의 해시 폴더가 바뀜 → 그램에서는 `~/bin/codex.cmd`가 최신 파일을 찾아 실행하도록 만들어 둠), Aider는 격리 환경(`~/tools/aider-venv`), Gemini는 `~/bin/gemini.cmd`(→ `agy.exe`). `~/bin`은 사용자 PATH에 등록됨. 전역 Python에 `aider-chat`을 설치하면 `numpy`/`protobuf`를 내려 `ortools`가 깨지므로 **설치하지 말 것**.
4. **원격 제어**: 라이젠에서 Claude 세션을 열고 원격 제어를 켜면 그램에서 지시 가능. 대화 맥락은 자동 이전되지 않으므로 **이 문서를 읽게 하는 것**이 인계 방법.
5. **Supabase 연결**: 이 세션의 Supabase 커넥터에는 `promise` 프로젝트가 없다(다른 프로젝트 2개만 있음). DB 확인·변경은 **사용자가 대시보드 SQL Editor에서 직접** 실행하는 방식이었다(개수만 세는 읽기 전용 SQL → 결과 확인).

- 쿠폰 링크가 존재하지 않는 `10promise.com` 을 가리키던 문제 -> `src/config/site.js`(`VITE_SITE_URL`, 기본 `https://10promise.co.kr`)로 통일. 한글 도메인은 이 환경변수 하나로 전환.
- 입찰 함수(accept_bidding, pass_bidding)와 서버 함수 18개가 로그인 없이 실행 가능했음 -> SQL 13.
- 고객은 Auth 계정과 비밀번호가 없어 `/mypage` 를 쓸 수 없는 구조(영향 없음, 고객 기능은 사업 결정).
- 배송 완료 알림이 존재하지 않는 열(body, related_id)을 써서 한 번도 저장되지 않던 오류 -> 08 의 함수가 실제 열(message)로 저장.
- 고객 화면의 쿠폰 등록은 DB 에 없는 열(used_by, used_at)을 써서 지금도 오류(사업 판단 필요, 보류).
- 코드는 profiles 를 열 목록(`src/lib/profileColumns.js`)으로 읽는다. profiles 에 열을 추가하면 이 목록과 DB 열 권한(13)을 함께 갱신해야 한다. `select('*')` 금지.

### 모델 역할 (교차 검토 원칙)
- 구현은 Codex(`codex exec --sandbox workspace-write`, 프롬프트는 stdin), 독립 검토는 Codex + Gemini(`agy.exe`, stdin, 도구 없이 텍스트만).
- **Gemini 3.8 Flash 도 구현 가능**(2026-10-20 시험 통과): `agy.exe --mode accept-edits --model "Gemini 3.8 Flash (High)"` 에 프롬프트를 stdin 으로 넣고, 고칠 파일을 프롬프트에 명시하고 "셸 명령은 실행하지 말 것"을 적는다. 작업 폴더에서 실행한다. 끝나면 반드시 `git diff` 로 변경을 직접 확인한다. Codex 한도가 소진되면(이 환경에서 Codex 는 한도 초기화 시각이 있다) Gemini 로 구현을 이어간다.
- Antigravity 안의 Claude Opus 4.6 / Sonnet 4.6, GPT-OSS 는 Gemini 와 별개 한도라 Claude Pro 를 아끼면서 최종 검토에 쓸 수 있다(`--model "Claude Opus 4.6 (Thinking)"`, 읽기 전용은 `--mode plan`).
- 두 모델의 지적은 **코드와 DB 사실에 대조해서** 받아들이거나 기각한다(Gemini 는 실제와 다른 지적이 많았고, Codex 는 코드 대조에 강했다).
- DB 확인은 사용자의 로그인된 Supabase SQL Editor 를 Chrome 으로 제어한 읽기 전용 쿼리로 했다. DB 변경 SQL 은 사용자가 직접 실행한다.

### SQL 을 고치면 항상 (2026-10-20 교훈)
- 1차 SQL 이 DB 에 안 들어간 원인은 `01b` 의 `$$` 오타(자동 치환 중 `$` 하나로 줄어듦)였다. 사용자는 적용했다고 했지만 공개 키 동작 시험(함수 404, commission_policies 3행 노출)으로 미적용을 확인했다.
