## 2. 적용 전 준비
1. **백업**: Supabase 대시보드에서 DB 백업 시점 확인(Free 플랜이면 수동으로 `pg_dump` 불가 → 스키마·함수 정의를 `_sql_admin_dealer/_운영본문/`와 노트 폴더에 이미 보관: 정산 함수, 배정 함수, 트리거, 정책). 적용 직전 읽기 전용으로 한 번 더 저장.
2. **사건·정산이 0건인 지금이 가장 안전한 시기**입니다(2026-11-04 확인). 운영 시작(11/17) 전에 적용하는 것을 권합니다.
3. **알림 보호**: 적용 중 사건·프로필을 건드리지 않으므로 알림 트리거(`funeral-case-alert`, `profile-signup-alert`)는 그대로 둡니다. 적용용 SQL은 사건·프로필 행을 수정하지 않습니다(예행연습에서만 일시 비활성).
4. 적용은 **Supabase SQL 편집기(ego-browser)에서 파일을 하나씩** 붙여 넣어 실행하고, 매번 아래 읽기 전용 점검을 합니다. 한 파일이 실패하면 그 파일은 자동으로 되돌려지고(단일 문장 실행) 다음으로 넘어가지 않습니다.

## 4. 웹 배포와 Edge Function
- **순서**: 위 SQL 18개가 끝나고 점검이 통과한 뒤 → 웹 푸시/배포 → send-alert 배포.
- **웹(Vercel)**: `admin-dealer` 브랜치를 푸시해 미리보기에서 화면 확인 후 main 병합(병합·푸시는 사장님 승인 후 제가 진행). 새 컬럼이 아직 없는 상태로 화면이 먼저 나가도 깨지지 않게 만들어 두었지만, SQL을 먼저 적용하는 순서를 지키세요.
- **send-alert**: 지역 알림 코드가 들어 있습니다. 설정 '지역별 알림 단위'가 끄기(기본)인 동안은 동작이 이전과 같고, 지역 판정 호출이 실패해도 기존처럼 발송합니다(fail-open). 배포 시점은 웹 배포 직후 권장. 배포 명령은 `supabase functions deploy send-alert`(사장님 승인 후 제가 진행하거나 사장님이 실행).
- 문자 발신번호 등 기존 설정은 변경하지 않습니다.

## 5. 마지막 단계(별도 승인): P1d 기존 열 제거
`partners.bank_account` 열 삭제 파일입니다. 계좌 등록이 0명이라 데이터 손실은 없지만, 화면이 새 표를 쓰는 것을 확인한 뒤(프로필에서 계좌 저장→재조회) 따로 진행합니다.

## 6. 알려진 위험과 아직 안 한 것 (정직하게)
1. **P6 영향 범위**: 프로필 조회를 좁히는 큰 변경입니다. 시험은 관계 규칙과 우회 차단을 확인했지만, 모든 화면을 실제 계정으로 눌러 본 것은 아닙니다. 위 '반드시 해 볼 것'이 필요합니다.
2. **연락처 노출 잔여**: 관계가 있는 상대에게는 같은 프로필 행의 푸시 토큰(fcm_token)·이메일 등이 함께 보입니다. 컬럼 단위 제한은 이번 범위 밖입니다(다음 작업).
3. **정산 계산이 읽지 않는 4개 금액**: 화면에 '확인 필요' 배지로 표시했습니다. 반영하려면 정산 함수 수정(사장님 결정).
4. **대표마스터 수수료**: 집계·설정만 있고 실제 지급 정산서 생성은 없습니다(변호사 확인 전 금지). 단가는 0원 기본.
5. **p1j(등급 판정 통일)**: 주요 화면은 공용 함수로 통일했으나 일부 화면(예: 지갑 화면, 옛 role='master' 분기)은 그대로입니다. 동작은 변하지 않습니다.
6. **시험의 한계**: 사건·정산이 0건이라 실제 운영 데이터 이행 시험은 없습니다. 시험은 트랜잭션 안에서 만든 임시 데이터로만 했고 모두 롤백됐으며, 매번 시험 직후 운영 DB에 시험 데이터가 남지 않은 것과 알림 트리거가 켜져 있는 것을 확인했습니다.
7. **린트**: 기존 프로젝트의 린트 오류 143개는 그대로입니다(이번 변경과 무관). 빌드는 통과합니다.
8. **취소 시 이미 지급된 정산 환수**, **정지 기간 미지급** 등 정산 규칙은 3단계(변호사 확인 후) 범위입니다.

## 7. 전체를 되돌려야 할 때
- DB: 3장 표의 되돌리기 문장을 **역순(18→1)** 으로 실행. 사건·정산이 쌓이기 전이라면 대부분 DROP만으로 충분합니다. 적용 후 데이터(승격 요청, 이력, 지역 선택, 홍보 동의 값)는 삭제됩니다.
- 웹: Vercel에서 이전 배포로 롤백(즉시).
- send-alert: 이전 버전 코드로 재배포.

## 8. 예행연습(시험) 재실행 방법
`_sql_admin_dealer/_시험/README_시험.md` 참고. 요약: `node build_all_dryrun.mjs` 로 `ALL_DRYRUN.sql` 생성 → Supabase SQL 편집기에 붙여 실행 → 마지막 오류 메시지(`DRYRUN_RESULT`) 안의 PASS/FAIL 목록 확인. 항상 자동 롤백됩니다(알림 트리거 2개를 같은 트랜잭션에서 잠시 끄므로 실제 문자는 나가지 않음).

## 9. 적용 기록 (2026-11-04)
- 1~18번 SQL을 이 순서대로 적용하고 단계마다 읽기 전용 점검을 통과함(P1d 기존 열 제거는 미적용).
- 8번(P2a 계층 규칙)은 처음 실행에서 Supabase 경고창("RLS 없이 표 생성")이 떠서 실행되지 않았고(아무것도 적용 안 됨), 규칙 표에 RLS(읽기 허용·수정 관리자만)와 쓰기 권한 회수를 파일에 추가한 뒤 적용함.
